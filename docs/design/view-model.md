# 视图模型：文示二支 × 四叶选择

> 本文是视图系统的唯一设计依据；代码与本文不一致时，先改本文。
> 术语：四叶 = flow / column / slide / present；UI 刻度 =「文 栏│览 示」。
> flow 的键名刻意避开 page——给将来 Word 式 A4 分页的「纸面（paper）」叶让位。

## 1. 结构：两支四叶

```
 文（编辑态）                示（展示态）
 muya 进程内                 md2slides iframe
 ┌──────┬───────┐          ┌────────┬─────────┐
  flow  column            slide    present
  全文流 分栏               页览      放映
 └──────┴───────┘          └────────┴─────────┘
 空间轴：连续 → 离散         时间轴：全页可见 → 一次一页
 可编辑                      只读（真分页 · 真主题）
```

- **文示的分界 = 引擎边界 = 可编辑性边界**（"借进程不借 DOM"的空间化表达；
  跨组分屏时，分割条就画在引擎边界上）；
- 每支内部一根粒度轴，两轴**正交**——不存在跨支的单一粒度序；
- **表 / 图 / 本**是顶级正交视图（两个内容透镜 + CodeMirror 源码），不进这棵树。

**预留叶：paper（纸面，未实现）**——Word 式 A4 分页的编辑形态。落地时它是
**文支第三叶**（可编辑、按物理页切），树变为：

```
 文（编辑态）                          示（展示态）
 ┌─────┬──────┬──────┐              ┌──────┬────────┐
  flow  column  paper              slide    present
  全文流 分栏    纸面(A4)            页览      放映
 └─────┴──────┴──────┘              └──────┴────────┘
```

- `flow` 键名正是为它让位（page 会与物理页撞名）；届时 paper 的页边界是
  物理的（A4 高度），度量来源（muya 直测还是借渲染器实测）落地前再裁决，
  "借进程不借 DOM"的边界原则不变；
- 「页览」的"页"届时自然消歧：页 = 物理页，无论幻灯片还是 A4。

## 2. 选择模型

- 四叶**常驻平铺**在切换器上（刻度「文 栏 │ 览 示」，支间一道分隔线提示两根轴）；
- **配置选择式**：点一下选中、再点一下取消，搭配由用户自定，**至多两叶**：
  - 1 叶 → 该视图全屏；
  - 2 叶 → 分屏，左右按按钮序（flow < column < slide < present）——
    文左示右、细左粗右由顺序自动成立；
  - 已两叶时第三叶点不动（先摘一片才能换）；最后一片不可摘（不可选到零）；
- 表/图/本与四叶互斥：选中顶级视图时叶选择挂起不丢，切回即恢复；
- column 叶只对真有 `begin` 标记的文档显示；全屏 column 在标记消失时回退 flow
  （分屏中的 column 投影不回退——投影为空无害）；
- 选择与分割比例持久化；旧持久化形状（mainView/subView 二级结构）自动迁移。

## 3. 分屏交互

- 中间**分割条可拖**，比例记住（0.2–0.8）；**分屏时页宽滑块失效收起**
  （宽度控制被分割条吸收）；
- 单视图滑块回归：flow/表/图 = 内容列宽（页宽滑块）；present 无；页览 = 页缩放（声明未接线）；
- (览, 示) 两叶皆只读 = 预演/导航模式（PPT 缩略图 + 大页的姿态）；
- 键盘归属：分屏时编辑器保焦点；deck 只吃鼠标/触屏；deck 聚焦时 Esc 关自己。

## 4. 页览叶（slide）

- md2slides 渲染的**全部真实物理页堆叠**：真分页、真主题、（续）页重复表头；
  放大即原尺寸，非截图缩略图；
- 刻度名「览」：说动作与视态（全部页一眼尽收），不押内容形态——物理页将来是
  幻灯片还是 Word 式 A4 分页都成立；
- **溢出提示**：物理分页永不产出溢出页（装不下即切（续）页），"溢出"的诚实
  语义 = **一个逻辑页被切成 N 张物理页**——首页挂「N页」徽章、（续）页虚线
  描边，工具条报「N 页 · M 页溢出」。数据在 deck 手中（（续）标记），deck 侧
  打标，不需要 muya 侧配合。
