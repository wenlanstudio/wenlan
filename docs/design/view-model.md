# 视图模型：二组 × 六叶选择

> 本文是视图系统的唯一设计依据；代码与本文不一致时，先改本文。
> **编辑面、事务与投影语义以 `sync-design.md`（v2.2 基线）为准**；本文只管
> 叶的组织、选择状态与持久化，冲突时改本文。
> 术语：六叶 = flow / column / spare / page / slide / present；
> `spare` = 雪藏的备用逻辑页（旧 key `page`），`page` = 正式的物理纸页面
> （旧 key `paper`）。2026-11-05 二次调整后，key 与 UI 名已对齐。

**当前 UI 刻度（2026-11-05 命名调整）**：用户只会看到「文 栏│页 览 示」
（栏随文档有无 `begin` 标记显隐）。缘由：原「页」（逻辑页）与「纸」（物理纸）
两个刻度语义重复、难以区分，故把逻辑页雪藏、把物理纸提为正式的「页」。

| 现 key    | 旧 key    | 原 UI 名     | 现 UI 名 | 切换器状态                     |
| --------- | --------- | ------------ | -------- | ------------------------------ |
| `flow`    | `flow`    | 文           | 文       | 常显                           |
| `column`  | `column`  | 栏           | 栏       | 仅有 `begin` 标记时显          |
| `spare`   | `page`    | 页（逻辑页） | **备**   | **隐藏**，暂不启用（实现保留） |
| `page`    | `paper`   | 纸（物理纸） | **页**   | 常显，成为正式的「页」视图     |
| `slide`   | `slide`   | 览           | 览       | 常显                           |
| `present` | `present` | 示           | 示       | 常显                           |

**持久化迁移**：旧 localStorage 无 `leafSchema` 字段，加载时按
`page → flow`（旧逻辑页已雪藏，绝不能解释成新 `page`）、`paper → page` 映射；
新版写入 `leafSchema: 2`，其 `page` 直接按物理纸解释。没有版本号就无法区分
「旧 page」与「新 page」，会把用户送错视图。日后启用「备」只需清空
`HIDDEN_LEAVES` + 改 `LEAF_META.spare.label`。下文 §1–§5 是 2026-11-01 三次裁决
与 M4.3 的**实施记录**，其中「页 / `page` = 逻辑页」「纸 / `paper` = 物理纸」是
当时的称呼与旧 key，保留原貌，读时按上表换算。

## 1. 结构：二组六叶

```
 编辑组（写作姿态，连续块流）      展示组（成页姿态）
 muya 进程内                      页 = muya 进程内；览/示 = md2slides iframe
 ┌───────┬───────┐               ┌─────────┬──────┬──────┐
  文      栏                       页        览     示
  全文流  分栏                     物理纸    页览   放映
 └───────┴───────┘               └─────────┴──────┴──────┘
   不切    横切                      滚动      全景   时序

 〔备 = spare 逻辑页 / 旧 key page、原「页」：2026-11-05 起隐藏，实现保留待启用〕
```

- **组判据 = 姿态，不是可编辑性**（三次裁决）：编辑组 = 你在写文本（页界
  至多是提示）；展示组 = 你在看页（纸卡内同样可以直接编辑）。刻度回答
  "我在看什么"——可编辑性是**编辑面位置**属性，不押在叶子上（§2 不变量）；
- **引擎边界不与分隔线重合**：备/页都在 muya 进程内（可编辑），览/示在
  md2slides iframe（只读）。跨引擎分屏（文/栏 × 览/示）时分割条恰在
  引擎边界上；组内或页参与的分屏，分割条只是 UI 分隔；
- 编辑组一根切法规轴（不切→横切→纵切），展示组一根浏览轴（滚动→全景→
  时序），两轴**正交**——不存在跨组的单一粒度序；
- **表 / 图 / 本**是顶级正交视图（两个内容透镜 + CodeMirror 源码），不进这棵树。

**备（spare，旧 key page / 原「页」/ 逻辑纸；现隐藏）**——写作流 + 分页提示：连续块流不动，缝与页码是测量
结果的投影（M2/M3 方案升格为一等叶），版式基同纸叶钉死纸面宽度。参照
Word 草稿视图的「显示分页符」虚线——投影即真分页，写的时候知道"大概第
几页了"，轻量、零布局干扰。

**页（page，旧 key paper / 原「纸」/ 物理纸）**——Word 页面视图：内容被推挤进一张张固定纸卡
（A4/Letter，frontmatter 声明），页与页有真间隙，卡内直接编辑。度量来源
已裁决：muya 直测（全套裁决见 §5），"借进程不借 DOM"的边界原则不变；
「页览」的"页"自然消歧：页 = 物理页，无论幻灯片还是 A4。

**备/页共享同一套测量引擎**（旧称页/纸；同一贪心、同一页数、同一分页符/纸型链路），
只差渲染姿态——备不推挤只画缝，页推挤 + 卡片网格。**硬验收（屏显页数 =
printToPDF 页数）对两叶同时成立**（推挤不改块高，页数相同）。

## 2. 选择模型

- **五叶可见平铺**在切换器上（刻度「文 栏│页 览 示」，分隔线提示二组），第六叶 `spare`（备）由 `HIDDEN_LEAVES` 雪藏——`toggleLeaf` 拒选、持久化净化回 `flow`，不会出现「选中了看不见的叶」；栏格随文档有无 `begin` 标记显隐；
- **编辑面不变量：同一时刻至多一个活编辑面**（sync-design N1/D6）——可编辑性
  是编辑面位置属性，不押在叶子上。九个可编辑表面 = 六视图叶（本/文/栏/页/览/示）
  - 三块级编辑器（码/表/图，复用 Muya `ui/*`，**不是新叶**）。当前实现仍只有
    左 pane/全屏的 muya 活引擎可写，右 pane 与纸叶是只读投影；M2/M5 会把
    页/览/示的 fragment 点击接到稳定编辑层的完整规范块，届时
    **投影只读 ≠ 不可编辑**。
    **A″ 裁决 / M4.3b 的渲染实现保留**：全屏纸叶可见面 = 真分片投影
    （paperProjection），活引擎以 display:none 留任「隐藏服务后端」——bus
    导出/TOC 依赖 editor.vue 挂载，收起不占位（导出走序列化，不需要布局）；
    **原「纸叶分屏焦点编辑」预留随之作废**（真分片 + 卡内编辑不可兼得，
    见 §5 M4.3b 调研结论）；
- **事务不变量**（sync-design D2/M0 已落地）：九个表面的写汇入同一事务流
  （`sync/transactionHub.ts`），共享 docRevision、undo/redo 与 dirty/save；
  投影刷新自身不产生事务，外源 apply 按 txnId 只确认一次；
- **配置选择式**：点一下选中、再点一下取消，搭配由用户自定，**至多两叶**：
  - 1 叶 → 该视图全屏；
  - 2 叶 → 分屏，左右按按钮序（flow < column < spare < page < slide <
    present）——编辑左、展示右（组内同序）、细左粗右由顺序自动成立；
  - **唯纸×览、纸×示不配对**（v1 语义不成立：分屏要求两侧对同一文档做
    一致解释，而 md2slides 只服务幻灯片形态——览对 A4 文档 v1 不做、纸对
    幻灯片文档给不出幻灯片语义；全屏单叶不受此限），与它们相点即单选替
    换，持久化中的非法对净化为单片；(页, 纸) = 左活页编辑、右纸面投影
    （leafProjection 复用），v1 即开放；(页, 纸) 分屏的右纸面 = 真分片投影
    （paperProjection，A″）；
  - 已两叶时第三叶点不动（先摘一片才能换）；最后一片不可摘（不可选到零）；
- 表/图/本与六叶互斥：选中顶级视图时叶选择挂起不丢，切回即恢复；
- column 叶只对真有 `begin` 标记的文档显示；全屏 column 在标记消失时回退 flow
  （分屏中的 column 投影不回退——投影为空无害）；
- 选择与分割比例持久化；旧持久化形状（mainView/subView 二级结构）自动迁移。

## 3. 分屏交互

- 中间**分割条可拖**，比例记住（0.2–0.8）；**分屏时页宽滑块失效收起**
  （宽度控制被分割条吸收）；
- 单视图滑块回归：文/表/图 = 内容列宽（页宽滑块）；present 无；览 = 页缩放（声明未接线）；备/页 = 页缩放（版式基钉死纸面宽度，同族待接线，见 §5）；
- (览, 示) 是**同一投影的两种姿态**（预演/导航 + 全屏放映，sync-design D8）；
  iframe 内自主测量、分页与 fit，但**可产生编辑意图**并汇入同一事务流（M5）；
  当前实现仍只读，待协议握手与稳定编辑层落地；
- 键盘归属：分屏时编辑器保焦点；deck 只吃鼠标/触屏；deck 聚焦时 Esc 关自己。
  **示中编辑时 Esc 先取消当前块编辑，无活编辑面时 Esc 才退出放映**；编辑态中
  步进/翻页键让位于文本输入（D6）。

## 4. 览叶（slide）

- md2slides 渲染的**全部真实物理页堆叠**：真分页、真主题、（续）页重复表头；
  放大即原尺寸，非截图缩略图；
- 刻度名「览」：说动作与视态（全部页一眼尽收），不押内容形态——物理页将来是
  幻灯片还是 Word 式 A4 分页都成立；
- **溢出提示**：物理分页永不产出溢出页（装不下即切（续）页；超高媒体原位
  等比缩放），"溢出"的诚实语义 = **一个逻辑页被切成 N 张物理页**——首页
  挂「N页」徽章、（续）页虚线
  描边，工具条报「N 页 · M 页溢出」。数据在 deck 手中（（续）标记），deck 侧
  打标，不需要 muya 侧配合。

## 5. 页/纸叶设计裁决（2026-11-01，三次裁决）

> **命名注（2026-11-05）**：本节是历史裁决记录，「页」指旧 key `page`（逻辑页，
> 现 key `spare`、隐藏为「备」）、「纸」指旧 key `paper`（物理纸，现 key `page`、
> UI 名为「页」）。称呼与 key 按当时原貌保留，读时按文首映射表换算；实现契约
> （共享测量基座等）不受影响。

> 概念对照（参照系 Word）：**页面视图 = 纸叶（物理纸）**；**草稿视图 +
> 「显示分页符」虚线 = 页叶（逻辑纸）**；页面设置（纸型/边距）= frontmatter
> 文档级声明；分页符（Ctrl+Enter）= HTML 注释标记；打印预览 = 既有打印链
> （printService → printToPDF），不新造。`---` 在纸面文档保持水平线语义——
> 幻灯片的逻辑分页语法不搬进来。写作与排版是两个任务（Word 同时养草稿与
> 页面两视图的同一理由），故分双叶。

- **度量来源 = muya 直测**，不借渲染器实测（页/纸共用）：
  - 单一版式真源：打印链本就用 muya 的 exportStyle.css 渲染；屏显注入与
    `@media print` 同源的版式基（字号/行高/页宽以物理单位出变量），编辑
    所见 = 打印所得——Word 页面视图的全部价值主张；
  - 对称性：§4 的哲学是"数据在 deck 手中，deck 侧打标"；页/纸是 muya
    进程内的叶，页界是自己的事，量自己的 DOM 在"借进程不借 DOM"边界之内；
  - 复用算法不复用进程：md2slides `overflow.js` 的分配核心（搬块/切块/
    （续）页/表头重复）抽成无 DOM 依赖的纯函数包——块高序列 + 页高 +
    策略封闭集 → 分配 + diag——双端各自量 DOM 各自调用（顺 IR_v3 A2/A3
    语义与分页解耦的方向）；策略封闭集须全参数化（至少：widow-fill 0.35
    / core-break-fill 0.25 / 媒体原位缩放 / TOC slack 12px / 家具克隆），
    deck 侧以快照回归锁行为；
- **双姿态共享一套测量**（三次裁决的核心；纸叶表征经 **M4.3 裁决（2026-11-02，
  用户拍板 A）修订**）：
  - **页 = 连续流 + 缝叠加（逻辑纸）**：块流不动，缝/页码是测量投影，
    版式基同纸叶钉死纸面宽度（Word 草稿视图的分页符 = 真分页的轻量投影，
    宽度游离则投影失真）。M2/M3 的实现原样升格为一等叶——轻量、零布局
    干扰，超长文档的写作档。v2 起缝可落行/行界（行级拟合，见下）；
  - **纸 = 真分片页卡（物理纸；M4.3 裁决，推翻"单一连续流 + 推挤"）**：
    纸叶按拟合结果把 block 真分散进页卡容器（**走 muya columns 的既成
    模式**——栏叶已验证"容器重组 + 活编辑"可行，页容器 = 分页驱动的
    同款重组）。切分真渲染：段落切行续行进续页、表格行切 + 续页克隆
    表头（续表）、卡片即页（无推挤、无灰隙穿越）。M3.5 的推挤级联
    （computePagePushes + margin-top 应用）在切换时**完成使命退役**——
    推挤存在的唯一理由是"连续流必须推到网格"，真分片下卡即容器、内容
    天然贴卡顶；测量基座 / 卡层 overlay / 缝线页码 / 分页符族 / 纸型
    全部沿用。已知代价（裁决时点破并接受）：muya 活引擎下拆 DOM 的编辑
    归属是 M4.3b 的主工程（跨页块克隆尾部的编辑语义、undo 边界、光标
    跨页），硬验收链路随切换重建；
- **裁决沿革**：一次裁决（§5 初版）预留 paper 叶并定度量来源；二次裁决
  （纸卡观感）曾将刻度改为「文 栏│纸 览 示」；用户随后点破**逻辑纸/物理纸
  之辨**——M2/M3 已建成的缝叠加本就是"逻辑纸"，纸卡是"物理纸"，二者皆
  有独立价值 → **三次裁决：二组六叶**（本节 + §1），M2/M3 工作升格为页叶
  而非退役；
- **M4.3b 调研结论（2026-11-02，裁决 A 的可行性核查）**：「真分片容器重组 +
  卡内编辑」在 muya 现架构下**无干净路径**——
  1. 分栏史实证伪 DOM 层重组：`editorLayout.ts` 因三条硬约束被删（插入锚点
     NotFoundError / 撤销栈空 / 保存走不通，见 muya `utils/columns/DESIGN.md`
     §1），纸卡内编辑踩同一批雷；
  2. 结构进块树（分栏的最终方案）成立的前提是**结构编辑不变**：栏成员关系
     由标记钉死、键入不改结构；页成员关系随每次键入重排 → json1 op path
     （`[3,0,1]` 型寻址，columns/column 的 `path` 覆写即此机制）不断改写 →
     撤销栈失效。这是 OT 寻址的根本冲突，非工程量问题；
  3. 分栏结构是**导入期标记推导**（`markdownToState._buildColumnGroups`），
     无 begin 标记的文档根本没有结构可借——而分页须对**所有**文档生效；
  4. 引擎插入锚点与 DOM 1:1 耦合（`Parent.insertBefore` 同时走
     `children.insertBefore` + `domNode.insertBefore` + json1 op）——视图层
     把块搬进页容器的任何做法都打断这只三角。
     **推论**：「真分片渲染」与「卡内可编辑」不可兼得——真分片只能活在
     **只读面**（deck 式重建的投影，或打印链 Chromium 原生切分）。M4.3b 路径
     据此重裁（见落地切片）。
- **切页策略分级**：v1 块级 keep-together（缝只落块边界，跨缝难题不存在）；
  超整页块降级 = 穿缝（缝线虚线让过），**不缩字号**（Typora"段落过高且缩
  至字号下限"之坑在设计层堵死）；v2（M4.3）：**拟合引擎升行级**——段落
  跨页切行（widow/orphan ≥ 2，内核 `cutLinesFitting` 镜像 Chromium）、
  表格行切 + 续页克隆表头（内核 `countFittingPrefix`，headH 每页占一份）、
  代码块暂维持 keep-together（M4.3 范围外）——**屏侧拟合与 Chromium 原生
  切分逐条等价**（打印链同步去掉段落/表格的块级 break-inside:avoid，避免
  屏打两套切分语义），硬验收持续把关，任一不对齐回退块级；
- **分页符 = HTML 注释标记族**：`<!-- pagebreak -->`，与 column 的
  `<!-- begin/split/end -->` 同族——不占 `---`、纯文本可移植；注释不渲染
  **内容物**（区别于 `---` 的水平线），但按族惯例渲染编辑态徽标（⤓ 分页
  符，与 mdcols 徽标同款 affordance，栏视图随族隐藏）；屏测读徽标作强制缝
  （本页无正文时镜像 Chromium 语义忽略——连续/文首分页符不产空白页），打印
  链由 exportHtml 把注释行换成零高标记 div 走 `break-after: page`；纸型/
  边距归 frontmatter（`paper: A4|letter`）：屏侧几何随之变，导出对话框
  打开时纸型默认值取自文档声明（未声明保留用户上次选择），屏打两侧默认
  同纸；
- **交互入位**：按钮序 flow < column < spare < page < slide < present
  （编辑左、展示右自动成立）；页/纸皆常显（任何文档都有这两种页面视图，
  不学 column 的"有标记才显示"）；配对规则见 §2（唯纸×览/示不配）；
  页/纸单视图滑块 = 页缩放（版式基钉死纸面宽度，A4 常超窗宽，缩放是刚
  需，与览 slide-zoom 同族，均待接线）；
- **「览」对 A4 文档**：v1 不做（纸自身已按页可见，页览冗余）；将来走
