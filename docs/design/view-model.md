# 形态模型：从连续到离散（视图系统的统一设计）

> 状态：**设计冻结，分阶段落地**。本文是视图模型（形态 × 投影面）的唯一设计依据；
> 代码与本文不一致时，先改本文。讨论沉淀于 2026-10-31，正名与三层卡片为用户裁决。

## 1. 一条轴：离散度单调递增

文档有四种形态，排在一条"离散度"单调递增的梯子上：

```
page ──── column ──── slide ──── present
 全文      分栏        分片        演示
极度连续                            极度离散
```

"离散"有三重，逐级叠加，梯子的顺序由此定义（不是排出来的）：

| 形态    | 空间                 | 内容单元                  | 时间                         |
| ------- | -------------------- | ------------------------- | ---------------------------- |
| page    | 连续                 | 无（纯流）                | 全在                         |
| column  | **离散**（横向分块） | 连续（跨栏流）            | 全在                         |
| slide   | 离散                 | **离散**（卡片=语义单元） | 全在                         |
| present | 离散                 | 离散                      | **离散**（一次一页，基数=1） |

- 极度连续 = `<page>` 全文；极度离散 = `<present>` 全屏放映。
- **正名**：形态名一律单数（page / column / slide / present）——复数是"视图时代"
  的遗产（"装着许多栏/片的视图"），单数说的是**文档以何种形态呈现**。
  形态用单数（column），块树结构用复数（`columns` 块），名实各归其位。
- present 不是"文档的片"：它是 md2slides 的**成片**（另一渲染器、iframe 进程）。

这条轴也是**两个引擎的分工线**：

- slide 及以下的离散（哪些内容属于一卡）是**语义判断**，muya 块树自己就知道；
- present 的离散（这卡装不装得下 16:9）是**物理判断**，只有真渲染实测能回答。

这就是 md2slides「借进程不借 DOM」裁决的另一种表述。

## 2. 分屏规则：离散先后关系的有序对

`<x>` = 单形态全屏；`[x, y]` = 左 x 形态可编辑，右 y 形态只读投影。

**合法对 = 离散度严格递增的有序对**（"离散先后关系"）：

- 左侧 ∈ {page, column, slide}（可编辑的 muya 透镜）；
- 右侧 ∈ 比左侧离散度更高的任一形态（投影面）。

全部 3+2+1=6 对：[page,column] [page,slide] [page,present] [column,slide]
[column,present] [slide,present]。相邻对是逐级验证，跨级对（含
[page,present]——用户裁决放行）是"直接看着成品写"。

**两套投影面机制**（不增加第三套）：

| 投影面      | 内容           | 机制                                                             |
| ----------- | -------------- | ---------------------------------------------------------------- |
| muya 投影面 | column / slide | 同 markdown 的只读第二 muya 实例，挂对应 lens                    |
| deck 投影面 | present        | md2slides 本地服务 + iframe（slidesPresent 组件），放映/画廊两态 |

## 3. slide 形态 = 三层各归其位（卡片设计裁决）

**语义卡**（slide 透镜本体）：

- 边界只落在块上（标题层级 + `---`，与 md2slides `sectionize` 同族互锁，
  语料 `md2slides/e2e/fixtures/dialect/slidebreak.md` 是共同裁判）；
- 卡片用**属性 + 分段边框 CSS** 拼出：块打 `data-page="n"`（首块
  `data-page-start`），同页块共享背景/左右边框，首尾块圆角，页间 margin 拉开；
  **零 DOM 重组**——columns Phase 2 的教训（DOM regroup 断插入锚点/撤销/保存）。
  页不做块树真块：页边界是从标题层级推导的策略，不是源码记号，真块化会让
  "标题降级"绑架块树重组与撤销栈；
- 卡片**随内容生长**，不锁 16:9——逻辑页没有高度上限，锁比例必然说谎或穿帮；
- 卡内排版用 muya 自己的排版，不套 deck 主题（度量不同会打架）。

**物理徽章**（透镜上的批注，不是物理计算）：

- 每张语义卡角标「N页」：N = 该语义卡内容在成片里落在几张物理页上
  （按 deck build 的每页 src 段重叠计数；1 = 装得下，≥2 = 溢出或被吸附）；
- 数字来自 present 投影面的真实 build（`data-src-*`，md2slides API 本就暴露），
  **零物理复刻**——透镜不装懂物理；
- 语义页 → 物理页是 N:M（孤段吸附相邻核心组），徽章语义取"落在几张物理页上"；
- 独立 `<slide>`（无投影面）= 纯语义卡，无徽章——物理反馈需要 deck build。

**成片画廊**（present 投影面的画廊态，用户裁决：同一 iframe、同一 build）：

- 全部物理页堆叠展示：真主题、真（续）页、真重复表头——"大卡片 + 溢出小卡片"
  的家在拥有物理真相的引擎那边，不在 muya 里重造；
- 放映 / 画廊一键切换，不引入第四个投影面机制。

**为什么不在 muya 里画固定比例卡 + 溢出小卡**（调研结论，结构性）：

1. 物理边界落在块内部（表格按行、代码按行、列表按项），块粒度作画放不进去；
   要放就得切 DOM——columns Phase 2 的坑；
2. 装不装得下由主题度量决定（字体、padding、KaTeX、autofit 缩放），muya 自测
   = 用不同物理规律运行的第二分页器，与成片必然分叉（最坏的方言分叉：物理分叉）；
3. 业界同构：Marp 固定画布**静默裁切零警告**；Slidev 溢出只在旁边 preview 可见；
   PowerPoint 类能做是因为内容是画布对象而非文本流。

## 4. 与其余视图的关系

- table / figure 也是透镜（内容类型过滤），不在这条梯子上——梯子管"成片度"，
  透镜管"看什么"；两者正交；
- code/source 是独立渲染（CodeMirror），非透镜；
- 本模型只重组"文档的离散度呈现"，不动 table/figure/code 的既有地位。
