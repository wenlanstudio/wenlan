# 教学客户端与身份体系设计（edu-client v1 草案）

> 定位：对接教学服务端（文枢 wenshu-server，生态总名「文澜」）的学生侧客户端
> 设计：账号/登录、双窗口架构、教学客户端窗口（讲义/实验双模式）。
> 与 `view-model.md` 互引——教学客户端复用其视图叶，不新增叶。
>
> 状态：**设计草案**（2026-11-07 三轮讨论定稿；同日服务端定名文枢
> wenshu-server，M1 前后端闭环已跑通；2026-11-08 §5.3 补作业题目卡锚点）。
> §8 决策 D1/D2/D3 已全部拍板。

## 1. 需求与已拍板决策

- **N1 登录可选，不设墙。** 未登录 = 完整本地编辑器（现状一切功能）；登录只
  解锁服务端能力。登录不出现在启动路径上。这与 ZCode/WorkBuddy 类「账号即产品」
  有本质区别：文览是「本地编辑器 + 可选云身份」。
- **N2 双窗口。** 主窗口 = 文览编辑器，零侵入；登录后可打开独立的「教学客户端」
  窗口。学生副本与本地自由文件从物理上隔离，杜绝"编辑器里改讲义回传污染教师
  模板"的路径。
- **N3 讲义模式 = 完整多视图 + 只读引擎。** 文/栏/页/览/映全开（含「映」放映），
  "一文多览"闭环到学生侧；但引擎挂只读锁——学生不该改教师的作品。
- **N4 实验模式 = 仅文视图 + 活引擎可编辑。** 实验是交互流，flow 最合适；页
  视图的打印排版反而是负资产。可编辑范围随**发布用途**（发布物姿态字段）：
  - 机房实训（本地判）：全篇可编辑，学生副本零派生自由度优先；
  - 作业/测试/考试（服务端判）：锁区——仅题目卡/待填写区/代码块可写，其余只读，
    防误改防作弊、证据结构化。锁不锁客户端不提供选择 UI，读发布物数据照开关。
- **N5 服务端 M1 对齐。** 客户端 v1 = 登录 + 课程/讲义列表 + 讲义只读阅读。
  答题（M2b）、实验记步（M3）后续往壳里填组件，壳不再动。

## 2. 总架构：双窗口 + 共享层

```
┌─ 主窗口 · 文览编辑器 ──────┐      ┌─ 教学客户端窗口（独立）────┐
│ 未登录 = 完整本地编辑器      │登录后 │ 登录态 · 教学场景专用        │
│ 六视图编辑（本/文/栏/页/览/映）│ ───→ │ 课程/讲义/实验列表           │
│ 本地文件 · 文件树侧栏        │      │ 讲义阅读（只读多视图）        │
│ 侧栏底部账号条（登录入口）    │      │ 实验模式（文视图+块级作答）    │
└────────────┬──────────────┘      └────────────┬──────────────┘
             │            共享层（复用，不新写）    │
             └─────── 主进程 auth 模块 · muya · i18n · IPC ───────┘
```

- 两个 BrowserWindow 加载**同一个 renderer bundle、不同路由**，代码天然共享，
  不需要抽包；代价只是内存多一份实例。
- 窗口关闭语义：关教学客户端 = 离开教学场景，token 留在 main，下次秒进。

## 3. 身份与凭据（main 进程单例）

- **协议直接复用 yudao 自带 auth，不自研鉴权**：登录换
  `access_token + refresh_token`，请求带 `tenant-id` header。
- **token 只活在 main 进程**：Electron `safeStorage` 加密落盘 `~/.wenlan/`；
  renderer 只经 IPC 拿用户资料，token 不进 renderer（防 XSS）。
- main 提供：自动刷新、401 统一拦截、多窗口共享同一登录态（单例）。
- **租户（学校）选择**：登录框带学校选择（yudao 租户查询接口），首次选择后记住；
  机房场景可预置配置文件实现零操作，UI 保留兜底改租户。

## 4. UI 入口

| 位置                                                                    | 内容                                                                   |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **sideBar 底部账号条**（主入口，参照 ZCode/WorkBuddy 左下角账号条模式） | 未登录显示「登录/注册」；已登录显示头像+昵称，菜单含「打开教学客户端」 |
| preference 新增「账户」tab                                              | 学校（租户）信息、令牌状态、退出登录                                   |
| 登录动作                                                                | 独立小窗（BrowserWindow）或 sideBar 滑出面板，不塞 preference 深处     |

教学客户端窗口内也有账号条（顶栏右侧），两窗口共用 main 登录态，一处登录处处可见。

### 4.1 教师发布入口（增强路径：写完即发，不离开编辑器）

- 主窗口**登录后**出现「发布到文枢…」动作（文件菜单/账号条菜单）：
  对话框选课程/教学班、发布用途姿态（资料查阅/机房实训/作业/考试）→ 调
  wenshu 发布 API（上传当前文档 md）→ 服务端校验（fm `course` 缺失、quiz
  课程内 id 查重等，见 QUESTION-BANK）→ 发布物创建。
- **边界与 N1 一致**：未登录的通用编辑器表面零教学概念；发布对话框
  （课程选择/姿态）是登录解锁的服务端能力 UI，属合法居所；文览本地
  不做教学校验，只呈现服务端返回的错误。
- 浏览器 wenshu 管理端是**发布主路径**（理论课教师零安装，ARCHITECTURE
  ADR-14）：上传 + 服务端预览 + 发布；批量、版本与发布物管理、成绩统计也在
  这里——不进文览。
- 教学客户端窗口 v1 保持学生侧专注；教师管理视图走浏览器管理端。

## 5. 教学客户端窗口

### 5.1 布局

```
┌──────────────────────────────────────────────┐
│ 顶栏：课程切换 · 讲义面包屑         头像+账号条  │
├───────────┬──────────────────────────────────┤
│ 侧栏       │ 讲义阅读区                         │
│ 我的课程    │  ├ 正文（muya 渲染）               │
│ └ 讲义/实验 │  ├ 教学指令块：题目卡/步骤条/待填写区  │
│ 已下载     │  └ 底部实验控制台（M3 再上）          │
└───────────┴──────────────────────────────────┘
```

### 5.2 讲义模式（只读多视图）

- 挂只读锁的多视图管线，viewSwitcher 全量；「映」放映可进。
- 讲义正文存服务端 DB（服务端模型），客户端按发布物 id 拉取并缓存；拉到的是
  服务端派生的学生版 md：载荷已删，课堂题换成 `<!--quiz-slot-->` 标记（E4 渲染
  为插槽，之前不可见；见 TEACHING-SPEC §七）。

### 5.3 实验模式（文视图 + 块级作答）

- 锁定文视图（viewSwitcher 只留「文」），活引擎可编辑。
- TEACHING-SPEC 的 md 教学指令（题目/步骤/断言/待填写区）解析后渲染为**块级
  控件**，直接落在文视图流内：
  - 借鉴 #3 M2 的 `blockEditor` 思路（单块可写 Muya 实例 + Ctrl+Enter 提交 /
    Esc 放弃），从「页叶投影」挪到「文视图原位」——注意该实现留在
    `feat/sync-m2-page-edit` 分支，未合并；本文只取其思路，落地时独立实现；
  - `<!--quiz {...}-->` 类注释在 markdown-it core 规则解析、渲染成控件，
    classbuzz 已趟过同一条路；作业/考试学生版的 quiz 标记是派生改写的无 answer
    版（TEACHING-SPEC §七），题目卡据此锚定、收答案交 wenshu 判；
  - 代码运行（mdcode2run）为 M3，入口预留代码块控件位。
- 锁区实现：非作答块设只读（沿用「同一时刻至多一个活编辑面」约束）。

## 6. 数据与缓存

- 实验副本落 `~/.wenlan/coursework/<tenant>/<发布物id>/`，**绝不进常规文件树**；
  由教学客户端独占管理、可整目录清空。
- 讲义/发布物按版本缓存（服务端版本全量副本模型）。
- 提交 = 从块结构抽**限长证据**回服务端（作业/考试姿态）；机房实训本地判，
  结果回传记录。
- 学生副本永不写回教师模板：服务端「发布物管下发、学生副本管回收」的模型约束，
  客户端不提供任何直达路径（N2 的窗口隔离是第一道锁）。

## 7. 与既有设计的边界

- `sync-design.md` 已废弃（2026-11-07，文览目标改为一文多览）：本文不依赖
  它；多视图同步定位以 `view-model.md` §6 为准。
- classbuzz（竞答，学生端先做 H5，小程序后置，服务端并入中心服务器）：**学生登录
  system_users**（2026-11-07 修订：竞答为正式计分渠道，免注册冒名风险
  不可接受；H5 登录一次，同一手机下次免输；原「房间+
  学号免注册」降级为练习/试玩，不计正式成绩）。生产形态 = 竞答逻辑并入
  wenshu 单体（内嵌 ws，ARCHITECTURE ADR-6），Node 服务不进产品；题目来自
  题库（讲义发布链拆题入库，见文枢 ARCHITECTURE ADR-12），答题记录落库、
  **服务端直写**成绩册（客观可追溯）。
- paper / 页视图分页、N3 屏打硬验收、既有 e2e 护栏（paper-page-count 等）：
  不受双窗口影响，不涉新窗口。
- i18n：新增键 12 语言全加 + `pnpm minify-locales`（既有硬规矩）。
- 命名：生态总名「文澜」只做品牌/文档层，**不落代码标识**（文澜/文览同音，
  ASCII 均为 wenlan）；代码层各产品标识独立——编辑器 `wenlan` 不动，服务端
  已定名**文枢（wenshu）**，目录 `wenshu-server`（§8 D2 已拍板）。

## 8. 决策记录（D1/D2/D3 已全部拍板）

- **D1 学生账号体系（已拍板 2026-11-07：system_users）**。格局为三块
  不相交的人口，各归各位、互不需映射：
  - **师生（教学）= `system_users`**（admin-api，RBAC 兜）：名单导入驱动
    生命周期，正是 B 端形状；M1 教学六表/名单导入/管理页已建于此，地基
    不动。
  - **非教育用户（未来文览 AI/agent）= `member` 预留**：自主注册 C 端
    （app-api + 微信绑定），教学侧永不使用；yudao 单体双 API 面天然并存，
    届时把 M1 裁掉的 member 模块加回即可，届时再定 C 端租户模型（默认
    租户 vs AI 云独立部署）。若师生也要用 AI，走 wenshu 教学侧 agent +
    教学配额（学生已有 system_users 身份），不碰 member。
  - **classbuzz 竞答学生 = 登录的 system_users**（2026-11-07 当日修订：
    竞答升级为正式计分渠道，免注册的学号冒名风险不可接受；H5 登录一次，
    同一手机下次免输，小程序上线时再加 openid 绑定；免注册降级为练习/试玩
    模式不计成绩。见 §7 边界注记）。
  - 风险与对策：学生角色零菜单零权限，学生侧教学接口走独立权限串授权
    （RBAC 兜底）；协议面单一（admin-api + tenant-id），M1 已实测。
- **D2 服务端命名（已拍板 2026-11-07）**：文枢（wenshu），目录
  `wenshu-server`；候选文津/文源/文澜书院落选。
- **D3 注册渠道（已拍板 2026-11-07）**：教师/管理员导入学生名单 + 初始
  密码、首登改密（Excel 名单导入服务端 M1 已支持）；桌面端只做登录 +
  首登改密，自主注册留给 web 端。
