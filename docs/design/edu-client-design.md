## 1. 需求与已拍板决策

- **N1 登录可选，不设墙。** 未登录 = 完整本地编辑器（现状一切功能）；登录只
  解锁服务端能力。登录不出现在启动路径上。这与 ZCode/WorkBuddy 类「账号即产品」
  有本质区别：文览是「本地编辑器 + 可选云身份」。
- **N2 两个实例、同壳叠加（D10）。** 通用文览 = `WindowType.EDITOR` / `/editor`
  / `app.vue` 完整壳；教育版文览 = `WindowType.TEACHING` / `/teaching` /
  **同一套 `app.vue` 完整壳** + 教育侧栏/面板。两者是同一 bundle 的两个
  BrowserWindow 实例，共享 main auth 单例；**教育功能只做叠加，不换壳、不加
  第三条窗口类型**。登录态/RBAC 决定叠加层显隐与编辑面开关（教师全开、学生
  只读锁），学生副本与本地自由文件仍物理隔离。
- **N3 讲义模式 = 完整多视图 + 只读引擎。** 文/栏/页/览/映全开（含「映」放映），
  "一文多览"闭环到学生侧；但引擎挂只读锁——学生不该改教师的作品。
- **N4 实验模式 = 仅文视图 + 活引擎可编辑。** 实验是交互流，flow 最合适；页
  视图的打印排版反而是负资产。可编辑范围随**发布用途**（发布物姿态字段）：
  - 机房实训（本地判）：全篇可编辑，学生副本零派生自由度优先；
  - 作业/测试/考试（服务端判）：锁区——仅题目卡/待填写区/代码块可写，其余只读，
    防误改防作弊、证据结构化。锁不锁客户端不提供选择 UI，读发布物数据照开关。
- **N5 服务端 M1 对齐。** 客户端 v1 = 登录 + 课程/讲义列表 + 讲义只读阅读。
  答题（M2b）、实验记步（M3）后续往**同一套 `app.vue` 壳**里叠组件，壳不再动。
  > D10 细化（2026-11-09 20:28）：`/teaching` 现挂 `teaching.vue`（课程/讲义
  > 列表 + `reader.vue` 只读文视图），**不要求换壳重挂 `app.vue`、不做布局重构**，
  > 其列表作为侧栏内容来源复用。教育功能在各自现有布局上叠加，左下登录、
  > 右下视图切换、顶部菜单栏一律保留。

## 2. 总架构：两个实例 · 同一套壳 · 叠加层

```
通用文览   WindowType.EDITOR   /editor    app.vue 完整壳（本/文/栏/页/览/映 · 文件树 · 编辑面）
教育版文览 WindowType.TEACHING /teaching  app.vue 完整壳  ← 同一套，不换壳
                                          + 教育侧栏/面板（课程 · 发布 · 发题 · 成绩 · 管理）
                                          + RBAC：学生锁编辑面，教师全开
                     └───── 共享层：main auth 单例 · muya · i18n · IPC ─────┘
```

- **两个 BrowserWindow，同一个 renderer bundle、同一套 `app.vue` 完整壳**，
  只按窗口类型给不同默认路由（`routes(envType)`）；代价只是多一份 renderer
  实例，不抽包、不写第二套 UI。
- **教育功能是叠加态，布局零重构**：顶部菜单栏加「教学」菜单、侧栏加「教学」
  tab（课程工作区独立树，不与常规根混）、状态栏加教育指示；**左下「登录」、右下
  `viewSwitcher` 刻度、中间编辑区、六视图管线、文件树全部原样**；不新增常驻
  右侧面板、不改壳。未登录的通用实例表面零教学概念（N1）。
- **RBAC 在同一壳里切姿态**：教师 = 编辑面全开 + 教育面板全功能；学生 =
  编辑面挂只读锁（N3）+ 面板只剩「我的课程/我的作业」。**不另做精简只读客户端**。
- **教育版同样能用六视图辅助写讲义/实验手册**，但受 `view-model.md` §2/§6 的
  编辑面不变量约束：编辑面只有「文」(muya) /「本」(CodeMirror)，栏/页/览/映/
  表/图/码一律只读——是分屏预览、页叶看纸面分页、览叶看物理页堆叠、映叶
  预演放映，想改就跳回文/本，不在只读叶里就地编辑。
- **放映不另建窗口**：「映」叶（`deckPane.vue`）已是完整 deck 放映器——main
  本地 md2slides 服务 + iframe + `build{md, mdDir}` + `enterPresentImmersive()`
  全屏。E5 直接复用，教育版实例同样继承，不拉服务端 presentation HTML。
- **不内嵌 `wenshu-ui-admin`**：内嵌须把 token 写进 webview localStorage，破
  §3「token 只活 main」；教育面板是同一 renderer 的原生组件，走
  `window.auth.request`。
- 窗口关闭语义：关教育版实例 = 离开教学场景，token 留在 main，下次秒进。

## 3. 身份与凭据（main 进程单例）

- **协议直接复用 yudao 自带 auth，不自研鉴权**：登录换
  `access_token + refresh_token`，请求带 `tenant-id` header。
- **token 只活在 main 进程**：Electron `safeStorage` 加密落盘 `~/.wenlan/`；
  renderer 只经 IPC 拿用户资料，token 不进 renderer（防 XSS）。
- main 提供：自动刷新、401 统一拦截、多窗口共享同一登录态（单例）。
- **租户（学校）选择**：登录框带学校选择（yudao 租户查询接口），首次选择后记住；
  机房场景可预置配置文件实现零操作，UI 保留兜底改租户。

### 4.1 教师入口：发布 + 全量管理（叠加态，不离开文览）

- **D7（2026-11-09）**：讲义发布**主路径在文览**；**D9（同日，用户选 B 全原生）**
  把教师侧全量管理也收进文览、浏览器不再是教师日常入口；**D10（同日）**再把
  形态收敛为**叠加态**——教育功能挂在教育版实例的侧栏/面板上，不新建管理窗口、
  不写第二套 UI。理由：讲义是本地文件资产（md + `img/` 图片树），浏览器既看不到
  目录也读不到相对引用；管理与讲义、放映、成绩同属一条教师工作流，切出去就断。
- 教育版实例**登录后**出现「发布到文枢…」动作（文件菜单 / 工具条 / 教育面板）：
  对话框选课程/教学班、发布用途姿态（资料查阅/机房实训/作业/考试）→ 客户端
  自动收集当前 md 引用的图片 → 两阶段上传（资产先行、md + 清单随后，见
  `course-workspace-design.md` §9）→ 服务端校验（fm `course` 缺失、quiz
  课程内 id 查重、引用完整性等，见 QUESTION-BANK）→ 发布物创建。
  **教师全程不接触打包文件。**
- **教育侧栏/面板（D9/D10，E6）**：课程/班级/Excel 名单导入、讲义版本、
  发布物、题库、成绩册、课堂会话与发题、租户与平台管理，全部是 **`app.vue`
  壳内的原生组件/路由页**，直连 admin-api；**不内嵌 `wenshu-ui-admin`、不复用
  其组件**。边界理由见 §2（token 只活 main）与 `ARCHITECTURE.md` ADR-21/22。
- **边界与 N1 一致**：未登录的通用实例表面零教学概念；发布对话框与教育面板
  都是登录解锁的服务端能力 UI，属合法居所；文览本地不做教学校验，只呈现
  服务端返回的错误。
- **学生侧零安装不变**：手机 H5 竞答、任意浏览器查阅照旧（ARCHITECTURE §1.3）；
  收敛的是教师侧。代价 = 取消「理论课教师零安装」，教师端一律装文览。
- 教师**放映走「映」叶**（本地 md2slides 服务 + 一键全屏），发布走工具条/面板，
  管理走教育面板，按 RBAC 切姿态。`wenshu-ui-admin` 仅作运维/应急备用，
  不承载教师日常入口。

### 5.2 讲义模式（只读多视图）

- **复用 `app.vue` 完整壳**：`viewSwitcher` 全量、六视图与文件树原样在；学生态
  按 N3 给**编辑面**挂只读锁（不是换一个精简只读客户端），「映」放映可进。
- 讲义正文存服务端 DB（服务端模型），客户端按发布物 id 拉取并缓存；拉到的是
  服务端派生的学生版 md：载荷已删，课堂题换成 `<!--quiz-slot id="…"-->`
  （`engine/src/derive.js:91`）。**E4 已落地两步**：① `util/quizSlot.ts` 把该标记
  渲染成可见的引用块占位（题干选项仍不下发，slot id 保留作锚点）；② `teaching.race.opened`
  按 `questionKey === slot id` 命中后把占位换成题干 + 选项卡。
- **课堂跟随（真跟随，非仅指示）**：`teaching.session.page` 的 1 基页号经
  `util/classroomFollow.ts` 判成 `{page, locked}` → 宿主向 deck 页面发一条
  `md2s:follow`，由 `resources-src/md2slides/exec-present.js` 直调
  `window.deckFull.getPlayer().go(page)`（跨源 iframe 里只有那一层碰得到 player，
  与 ▶ 执行桥同源，**不改 md2slides 上游**）。`followLocked` 为真时该脚本在
  capture 阶段吃掉导航键，学生翻不走；宿主另在 `md2s:change` 上做 800ms 冷却
  的回弹，兜住点击/手势翻页。状态栏指示课堂进行中即可点入「映」叶全屏跟随。
- **教师侧（这一轮补齐"发"的一半）**：开班入口在**状态栏已有的教学指示旁**
  （`el-dropdown`，不新增面板）：未开课时列出当前文档发布过的班（本地发布元数据
  里的 `releaseId + className`），开课后显示「● 课堂中 · 班名 · 第 N 页 · 在线数」，
  下拉给「锁定跟随 / 允许学生自由翻阅」「结束课堂」。`teaching.classroom` 命令与
  「教学」菜单项提供一键路径（在课堂中则下课，否则开最近一次发布的第一个班）。
  main 侧 `teachingSocket.host()` 先查 `/class-session/get` 再决定是否
  `create`——教师连点两下不该堆出两条并行会话；页码由 `md2s:change` →
  `teachingSocket.page()` 上行（按页号去重）。**教师也 join 同一房间**（上报要走同一条
  ws），因此 `followTargetOf` 对 `role === 'host'` 恒返回「不跟随」：跟随自己会形成
  上报→广播→goto→change 回环，锁跟随更会把老师自己按在一页上。

### 5.3 实验模式（文视图 + 块级作答）

- 实验模式按 N4 **策略性收起**其他叶（只留「文」），活引擎可编辑；壳仍是同一套
  `app.vue`，不是另开实验专用窗口。
- TEACHING-SPEC 的 md 教学指令（题目/步骤/断言/待填写区）解析后渲染为**块级
  控件**，直接落在文视图流内：
  - 借鉴 #3 M2 的 `blockEditor` 思路（单块可写 Muya 实例 + Ctrl+Enter 提交 /
    Esc 放弃），从「页叶投影」挪到「文视图原位」——注意该实现留在
    `feat/sync-m2-page-edit` 分支，未合并；本文只取其思路，落地时独立实现；
  - `<!--quiz {...}-->` 类注释在 markdown-it core 规则解析、渲染成控件，
    classbuzz 已趟过同一条路；作业/考试学生版的 quiz 标记是派生改写的无 answer
    版（TEACHING-SPEC §七），题目卡据此锚定、收答案交 wenshu 判；
  - 代码运行（mdcode2run）为 M3，入口预留代码块控件位。
- 锁区实现：非作答块设只读（沿用「同一时刻至多一个活编辑面」约束）。

### 5.4 教育能力入口（最小叠加，D9/D10，E6）

- **不是独立窗口，也不新增常驻右侧面板**：教育能力以 ① 顶部菜单栏「教学」
  菜单、② 左侧栏「教学」tab 内的课程工作区独立树、③ 底部状态栏指示 三处
  叠加在现有布局上；RBAC 判定显隐（教师/管理员全功能，学生只见「我的课程/
  我的作业」）。N2 的隔离由**编辑面只读锁 + 入口裁剪**实现，不靠物理换壳、
  不改布局骨架。
- **分区**：① 讲义与发布（课程/班级/Excel 名单导入/讲义版本/发布物/
  「发布到文枢…」）；② 课堂（课堂会话、发题/揭晓、大屏榜单；**放映走「映」叶，
  不在面板内**）；③ 成绩（成绩册、答题记录、导出）；④ 平台（租户、账号与菜单
  授权，管理员可见）。
- **数据通路**：一律经 main 的 auth 代理 IPC 直连 admin-api，走 §3 的
  token / `tenant-id` 注入；不经过任何 webview，token 不进 renderer 存储。
- **交付分批（E6）**：发布/发题/成绩等高频动作先行（放映已在「映」叶可用，
  不在 E6 范围），租户/名单/题库等长尾后置；服务端 API 契约不变，过渡期
  `wenshu-ui-admin` 作运维备用兜底，不留能力真空。
- **不内嵌**：B 方案的硬边界——内嵌 admin SPA 须把 token 写进 webview 的
  localStorage（破 §3），且 UI 仍是 web 那套，不解决「不方便」。
- **布局零重构（20:28 细化）**：现 `/teaching` 的 `teaching.vue` 保留，课程/讲义
  列表作为侧栏内容来源；教育入口在其现有布局上叠加。**不设「换壳」前置任务**，
  左下登录、右下 `viewSwitcher`、顶部菜单栏全部原样。

## 6. 数据与缓存

- 实验副本落 `~/.wenlan/coursework/<tenant>/<发布物id>/`，**绝不进常规文件树**；
  由教学客户端独占管理、可整目录清空。
- 讲义/发布物按版本缓存（服务端版本全量副本模型）。
- 提交 = 从块结构抽**限长证据**回服务端（作业/考试姿态）；机房实训本地判，
  结果回传记录。
- 学生副本永不写回教师模板：服务端「发布物管下发、学生副本管回收」的模型约束，
  客户端不提供任何直达路径（N2 的窗口隔离是第一道锁）。
