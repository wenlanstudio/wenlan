# 多视图编辑同步架构（sync-design v2.2 基线）

> 定位：#3「双向同步」的设计基线。与 `view-model.md`（视图模型）互引：本文管
> 「编辑如何汇聚、投影如何发散」，视图模型管「叶子如何组织、状态如何持久化」。
> 冲突时以本文为准并同步修订 view-model.md（沿用其立法惯例）。
>
> 状态：**设计基线 + M0 已落地**（2026-11-06，分支 `feat/sync-m0-txn-adapter`）。
> N1 的九个可编辑表面、D2 的双向事务入口、D4/D7/D8 的页/览几何分治已拍板；
> D1–D8 作为后续里程碑的实施约束。M0 只统一写路径与 Revision，**不改任何投影
> 与编辑表面**；M1–M5 仍是设计约束。

## 1. 需求（从 #3 与多轮讨论蒸馏）

- N1 九个可编辑表面 = **六个视图叶（本 / 文 / 栏 / 页 / 览 / 示）+ 三个块级
  编辑器（码 / 表 / 图）**。本编辑 Markdown 原文；码/表/图是锚定在规范块上的
  就地编辑控件，复用 Muya `ui/*` 既有组件，**不是视图模型的新叶**。可编辑性与
  所在 pane、所在投影、是否全屏无关；全局只保留「同一时刻至多一个活编辑面」
  这一约束。
- N2 编辑过程中分页/分幻灯片自动跟随。本/文/栏/码为连续编辑；页/览/示的单块
  编辑在 commit 后跟随。参考文档上，从事务提交到可见投影更新的 P95 ≤300ms；
  防抖窗口内允许旧态，但不允许过期异步结果覆盖新态。
- N3 屏显分页 ≡ 打印分页。它是持续成立的硬验收，不因共享布局算法而豁免测试。
- N4 同一文档、同一事务流、同一 Revision：任何表面的修改都汇聚到同一文档，
  任何表面都从它发散。块树是规范化文档模型；本视图中暂时不能解析的源码是
  合法的瞬时草稿，不因解析失败而丢失或被旧文本覆盖。
- N5 架构可测试：编辑 = 可重放、可逆的事务，投影 = 带版本的推导；异步测量、
  构建和资源加载均可作废过期结果。

## 2. 公理（设计的物理边界）

- **A1 浏览器是唯一排版引擎。** 块的几何（行数、高度）只能由 DOM 测量得出，
  块树自身不知几何。排版模型 = 块树 + 测量回填的几何标注。
- **A2 Markdown 是交换格式，不是唯一的运行时模型。** 块 id 不落盘（保持文件
  干净、git 友好）；身份是会话级概念。规范化块树承载可解析文档，源码草稿承载
  编辑过程中的瞬时文本，两者用 docRevision 关联。
- **A3 一切写皆事务，一切读皆投影。** 用户意图 → 事务 → 模型；模型 → 布局 →
  投影。投影刷新自身不调用 apply；位于投影上的编辑器只在用户提交意图时产生
  事务。回环抑制是结构性的，不是纪律性的。

## 3. 总架构：One Document · Versioned Geometry · Many Projections

```
用户意图（九个可编辑表面）
   │ 事务（intent → txn，携带 baseRevision / origin / selection）
   ▼
[ 统一事务流 ]  串行提交 · 可逆 · 可合并 · 日志用于测试与审计
   ▼
[ 文档 SSOT ]  规范化块树 + 会话 id + docRevision
   │                ▲
   │                └──── [ 编辑会话 ] 源码/单块草稿、选区、组合输入
   ├────────────► [ 页几何基座 ] 固有测量缓存 + 上下文布局 + 版本化失效
   │                              └─► 页/打印策略
   ├────────────► [ 览/示 iframe ] 内部自主测量、分页、fit，版本化交换结果
   ├────────────► [ 各视图投影 ] block/fragment 锚定、滚动/光标恢复
   └────────────► [ 序列化 ] 防抖落盘 .md ／ 打印消费同一页分片树
```

四层职责：

| 层       | 职责                                           | 不负责             |
| -------- | ---------------------------------------------- | ------------------ |
| 文档模型 | 块结构、块身份、事务应用、Revision             | 几何、渲染         |
| 编辑会话 | 草稿、选区、IME、commit/cancel、基准版本       | 投影决策           |
| 几何基座 | 页/打印的固有测量、上下文布局、失效与调度      | 编辑语义、览 fit   |
| 投影     | 每视图 DOM、block/fragment 锚定、滚动/光标锚定 | 文档决策、自发写回 |

览/示有自己的 `layoutRevision`；它与页几何基座消费同一 `docRevision`，但不要求
产生相同测量结果或共享 DOM 测量缓存。

版本链统一为：

```
docRevision → layoutRevision → projectionRevision
```

每次事务提交递增 docRevision；布局和投影记录自己所消费的版本。所有异步结果
必须携带请求版本，过期结果直接丢弃。

## 4. 八个核心决策

### D1 块身份：会话 id + 全量重建重锚（不落盘）

- 会话内：为每个规范块分配 `blockId`；`WeakMap<Block, blockId>` 只是对象到 id
  的索引，不是身份语义的全部。id 只在内存，随文档会话管理。
- 重锚覆盖**所有整树重建**：`setContent`、`replaceContent`、外部文件变更、
  源码切换，以及采用整树重建的 undo/redo，而不只覆盖显式重解析。
- 重锚使用「有序结构 diff + 规范块状态哈希」。哈希必须覆盖类型、属性、文本和
  影响渲染的元数据，不能只哈希可见文本。
- 哈希撞车或重复内容无法可靠消歧时，放弃旧 id 并分配新 id；投影允许整块重建，
  **编辑、undo、光标恢复不得猜测目标块**。
- 投影上的写请求携带 `(docSessionId, blockId, baseRevision)`。提交时重新解析
  当前目标；版本过期或目标歧义时进入 rebase/取消流程，不得写入相似块。
- id 不落盘。它是视图锚和会话内编辑寻址手段，不是跨文档、跨客户端的永久身份。

### D2 事务：统一信封，复用 Muya ot-json1

```ts
interface Txn {
  txnId: string
  docSessionId: string
  baseRevision: number
  origin: 'muya' | 'projection' | 'source' | 'table' | 'figure' | 'disk' | 'undo' | 'redo'
  op: JSONOpList
  selectionBefore?: Selection
  selectionAfter?: Selection
}
```

- **不另起一套 replaceText/insertBlock 操作语义。** Muya 现有 ot-json1 op 是
  规范化文档的事务载荷；新表面负责把用户意图转换成 op，全部写路径汇入同一
  串行事务流。
- **入口是不对称的，不能假设所有写都在 apply 前排队：**
  - Muya 自源编辑（文/栏及撤销历史）先在内部 dispatch/apply，再发出
    `json-change`；适配层在同一 tick 把已应用的 op 包装成 Txn、分配 Revision
    并广播，**不得再次 apply**。
  - 外源编辑（本/码/表/图、页/览/示 commit、外部重载）先进入事务队列，
    再经 `updateContents` 等入口应用；其引发的 Muya 通知只作提交确认，按 txnId
    去重，不生成第二笔事务。
- 统一的是事务顺序、Revision、历史和通知，不是「所有写都先经过队列再修改
  Muya」这一物理时序。自源通知必须同步处理，不得延迟到宏任务后与后续输入
  重排；外源排队期间到达的自源编辑按实际 apply 顺序确定先后并校验基准版本。
- 全部写路径进同一事务流：文/栏的 Muya 编辑、本视图的 Markdown 原文提交、
  页/览/示单块 commit、码/表/图操作、外部重载及 undo/redo。
- 应用成功后递增 docRevision，广播 `doc-changed(txn, revision, affectedIds?)`；
  identity/no-op 不产生伪历史。
- **undo/redo = 可逆 op + 选区恢复，不是从头回放日志。** 直接复用 Muya History
  的 invert/compose/transform 能力；事务日志用于回归重放、诊断和未来传输。
- 明确合并边界：连续输入可按现有规则合并；一次 IME composition 是一个原子
  撤销边界；插入/删除切换、空白词界、跨块和跨视图操作按既有 History 规则分组。
- 外部磁盘变更与自己保存的 watcher 回声必须区分；后者不得再次生成编辑事务。

### D3 几何基座：固有测量与上下文布局分层

- **固有测量**可按内容寻址：行带、表头/表行高、列表/引用子单元高度等。
- **上下文布局**不可只按内容寻址：块 top/bottom、兄弟间距、margin 塌陷、
  列表序号、标题与后继关系、分页结果都依赖文档位置和邻居。
- 固有测量基础键为：
  `(renderSchemaVersion, blockType, blockStateHash, layoutMode,
styleFingerprint, contentWidth)`；仅资源依赖块追加 `resourceReadyKey`。
- **删除泛化的 contextKey。** 若某个上下文因子确实改变固有测量，必须转成
  显式键成分（如列表 marker 占宽归入 contentWidth）；否则该结果属于上下文
  布局，不进入固有测量缓存。
- `blockStateHash` 对完整规范块状态求值；相同可见文本但格式、链接、图片、
  语言或属性不同的块不得共用测量。
- **哈希不得在打字热路径全块重算。** 事务应用时只更新受影响节点及其祖先的
  增量状态摘要（分块 Merkle/滚动哈希等实现由 M4 技术验证选定），典型成本为
  O(变更片段 + 祖先路径)，整段替换等操作允许退化为 O(变更子树)。同步热路径
  只维护 blockStateVersion 和 dirty 标记；最终 hash 在测量/缓存查询前按需
  finalize，不对全文或未变化块重算。hash 未就绪时以版本隔离新测量，禁止复用
  旧 hash 对应的缓存。
- styleFingerprint 覆盖完整排版样式，而非只有少量 token；layoutMode 区分
  文/栏/页等共享测量宿主的布局，不能因「内容相同」跨布局误命中。
- 字体、图片、数学公式、图表未就绪时的高度是 provisional，不进入稳定缓存。
  全局字体就绪是所有文本稳定测量的前置闸门，使用全局资源世代失效，不塞进
  每个块键。块级 `resourceReadyKey` 按图片、公式、图表等块内实际资源集合
  派生，只对资源依赖块进键；无此类资源的纯文本块不含此成分，晚到的块内资源
  不得洗掉无关块缓存。受影响块之后的上下文布局仍按 D4 重算。
- 缓存需要容量上限/LRU 与版本清理；M4 必须记录增量 hash 的维护成本、碰撞
  策略和内存开销，先通过基准再启用缓存。
- 测量宿主使用同源 Muya 渲染规则，批量读、合帧写；测量和布局结果均携带
  docRevision/layoutRevision。

### D4 调度策略：页共享几何基座，览/示 iframe 内自治

- **页策略**：贪心碎片化（keep-together + 行级缝 + orphan/widow + 续表
  续号），产出页序列。即现 `paginateBlocksV2`。
- **览策略**：逻辑分组（标题起片等）+ 物理分页/fit-frame 缩放，产出幻灯片
  序列，不只包含逻辑分片；测量、布局与缩放均在 iframe 内完成。
- 两者共享文档模型、块身份、Revision、资源语义及可抽离的纯布局工具；**默认
  不共享 DOM 测量缓存、块坐标或分页结果**。只有性能数据证明值得时，才把
  可跨环境复用的纯测量模块纳入共同基座。
- 合法的页增量优化是「只重测 dirty 块 + 从编辑点重算后续流式布局与分页」；
  不允许只重测当前块便原样保留后续位置，因为编辑点之后的 top、间距和分页
  均可能变化。

### D5 投影：块锚 + 分片锚

- 每个可见视图一份 DOM；整块搬移优先移动，跨缝才克隆。
- 每个投影节点携带 `data-block-id`；跨页/跨片续体还必须携带
  `data-fragment-id` 及其对应的逻辑范围（如行区间、表行区间或子单元区间）。
- 同一 blockId 在多个 fragment 中出现是正常状态，反查不得假设 querySelector
  只命中一个节点。
- 用户点击续页/续片时，由 `(blockId, fragmentId, fragmentRange)` 确定编辑入口；
  文档写入仍以规范块为准。
- 滚动锚定按 blockId + fragmentId + 视口内偏移恢复；览/示的当前页保持优先
  使用内容锚，而不是仅保存页码。

### D6 编辑协议：九个可编辑表面，连续编辑 × 单块激活 × 块级编辑器

- **文/栏**：Muya 原生连续编辑；内部 apply 后由适配层同 tick 包装事务信封，
  不二次 apply。
- **本**：CodeMirror 连续编辑 Markdown 原文。源码草稿持续保留，防抖解析成功后
  生成事务；暂时无法解析时保留草稿、显示错误位置，不以旧规范块树覆盖用户输入。
- **码**：以文档中的代码块为编辑单元，按语言提供高亮、缩进及相应编辑能力；
  修改的是目标代码块的内容，不是整篇 Markdown 原文，提交后更新对应规范块。
- **页/览/示**：点击 fragment → 解析规范 blockId → 在稳定编辑层中激活该
  **完整规范块** → commit → 事务 → 增量重排。不得直接编辑带裁剪、translateY
  或隐藏溢出区域的克隆 DOM。
- **表/图**：各自编辑器/控件产生用户意图，经同一事务流写回，不另建私有
  undo、私有 dirty 或私有文档副本。
- **码/表/图控件的实现锚点**：复用现有 Muya `ui/*` 浮层组件，包括
  `tableColumnToolbar`、`imageToolbar`、`codeBlockLanguageSelector` 等，随单块
  激活在稳定编辑层复用。复用其交互与呈现，写操作必须经适配器进入 D2 事务流，
  不得绕过事务层直接修改文档。
- 单块激活期冻结该视图重排，编辑块允许暂时溢出页/片框；其他投影停留在
  最后已提交 Revision。commit 后统一刷新，Esc 放弃草稿。
- Enter 不作为所有块的通用 commit：代码块、列表、引用等保留自身换行语义；
  commit 快捷键与各块编辑规则显式定义。
- 「示」中编辑时，第一次 Esc 取消当前块编辑；无活编辑面时 Esc 才退出放映。
  编辑态中步进/翻页键让位于文本输入。
- 激活期间发生 undo、外部重载或文档切换时，按 baseRevision 做 rebase、保留
  草稿并提示，或明确取消；不得静默覆盖草稿，也不得把草稿写到错误版本。

### D7 样式单源：同源定义，分视图渲染契约

- 一套文档样式模块生成宿主与 iframe 的样式产物，并计算同一
  `styleFingerprint`；字体、字号、颜色、代码块 white-space、行高和字体回退
  不得维护两份常量。
- **页/打印是严格几何契约**：选择器作用域、纸张几何、行高、资源就绪规则和
  Page/Fragment 渲染必须一致，并以 N3 实测兜底。
- **览/示是自治投影契约**：共享基础排版定义与资源语义，但幻灯片画布、分片、
  fit-frame 缩放和步进样式由 md2slides 独立管理；不要求与页叶具有相同块高、
  坐标或分页结果。
- iframe CSS 由同一样式模块构建/注入，iframe 不得再自行覆盖同一份基础样式；
  视图专用规则使用独立作用域。styleFingerprint 不一致时不得混用新旧样式和
  构建结果，应先同步样式再重建。
- 今天屏打两侧 pre-wrap/行高的对齐战就是双样式源的代价；D7 用来消除分叉，
  但不替代 N3 的真实 printToPDF 验收。

### D8 览/示：同一投影，iframe 内自治布局与版本化交换

- 览 = 全部幻灯片投影；示 = 同一投影的单页/全屏放映态 + 步进控制器。
  两者共享内容、编辑协议和 Revision，不再各自维护可写文档副本。
- md2slides 保留逻辑分片、物理分页、步进/放映立法作为策略库；其 Typora
  宿主壳维持原状。
- **首阶段保留 iframe，并拍板览/示在 iframe 内自主测量、分页和 fit。** 不把
  跨进程 DOM 测量 RPC 或页测量缓存复用作为 #3 的前置条件。
- postMessage 构建请求至少携带 `(docRevision, renderSchemaVersion,
styleFingerprint, resourcePolicyVersion, viewport, slideSize)`；响应回带上述
  消费版本、览自己的 `layoutRevision` 和 `resourceReadyKey`。宿主与 iframe
  均拒绝过期响应或指纹不一致的混合结果。
- 字体、图片、公式和图表在 iframe 内就绪后才能冻结览布局；资源状态通过
  `resourceReadyKey` 和就绪事件显式同步，而不是假设宿主资源就绪等于 iframe
  资源就绪。
- 编辑意图也携带 docRevision/baseRevision、blockId/fragmentId 和 txnId；iframe
  的投影刷新本身不产生事务，继续复用资源白名单、CSP 隔离、图表 RPC、代码
  运行及 PPTX 导出。
- 同进程化是后续独立优化：只有在测量复用或性能收益经数据证明后才实施，
  不与九个可编辑表面的首个闭环捆绑。

## 5. 打印等价（N3 的实现与验收）

屏显与打印应消费**同一份 Page/Fragment 树**，而非仅共享分页决策后各生成一套
内容 DOM：

- 页序列、切缝、续表、续号和 fragment 内容由同一布局结果产生；
- 打印 HTML 按页显式分盒，页盒尺寸、边距和内容与屏显同源；
- 字体、图片、公式和图表就绪后才能冻结最终布局并打印；
- Chromium 仍负责真实排版与打印，不能先验宣称不会再次分页。

因此 N3 是「同一分片树 + 固定页盒」支撑的工程不变量，而不是免测试的构造性
证明。`paper-page-count.spec` 永远保留硬验收：屏显页数 = printToPDF 页数，
并继续覆盖页界附近的段落、pre、表格、列表与引用。

## 6. 事件纪律与异步一致性（回环抑制）

```
Muya 自源：用户输入 → Muya apply → json-change ─┐
                                                 ├→ 统一事务流 → doc-changed(revision)
外源输入：用户意图 → 事务队列 → updateContents ──┘         → 布局/投影只读更新
```

两条入口汇合后只广播一次；外源 apply 引发的 json-change 按 txnId 作为确认消费，
不得再次分配 Revision。

- 纯投影刷新路径上不存在进入 apply 的入口；投影内编辑器只在用户 commit 时
  产生事务。
- 测量、setContent、览构建、图表渲染、字体/图片加载均可异步完成；回调先检查
  请求 Revision，过期即丢弃。
- 自己保存产生的文件事件按保存事务/文件指纹抑制，避免 disk → txn → save →
  disk 的回环。
- 测试：全局 monkey-patch apply，纯投影刷新期间断言零调用；另以乱序异步响应
  断言旧 Revision 永不覆盖新 Revision。

## 7. 风险与权衡

| 风险                               | 评估     | 缓解                                                            |
| ---------------------------------- | -------- | --------------------------------------------------------------- |
| 重复内容重锚误配                   | 中危     | 有序 diff + 完整状态哈希；歧义即新 id；写操作二次解析与版本校验 |
| 新事务层与 Muya History 分叉       | 高危     | 复用 ot-json1 与逆操作；统一信封，不另造撤销语义                |
| 自源/外源入口重复应用或重排        | 高危     | 自源 apply 后同 tick 封装；外源先排队；txnId 去重               |
| 本视图中间态不可解析               | 必然发生 | 源码草稿为一等编辑状态；错误定位；禁止旧模型回盖                |
| 分片克隆中直接编辑导致不可见光标   | 高危     | 稳定编辑层编辑完整规范块；fragment 只负责定位                   |
| 几何缓存误命中或缓存未就绪测量     | 中高危   | 固有/上下文分层；增量状态 hash；资源就绪键；LRU                 |
| 宿主与 iframe 样式/资源版本错配    | 高危     | 同源 CSS 产物；指纹握手；独立资源就绪键；过期结果拒收           |
| 冻结分页期间视觉溢出页/片框        | 可感知   | 溢出限当前编辑块并高亮；commit 即收                             |
| 异步构建乱序覆盖新内容             | 高危     | 全链路 Revision；过期结果作废                                   |
| 激活期间 undo/外部重载造成草稿冲突 | 中高危   | baseRevision 校验；rebase/保留草稿/显式取消三选一               |
| 去 iframe 破坏现有能力与隔离边界   | 高工程量 | 与同步解耦；首阶段保留 iframe                                   |
| undo 后跨视图滚动/光标跳变         | 体验问题 | 事务携带选区；投影按 block/fragment 锚恢复                      |

## 8. 验收场景（可测试的 N1–N5）

1. 本/文/栏/页/览/示/码/表/图分别修改同一文档，均进入同一事务流；其他视图
   在各自约定时机更新，dirty/save 状态一致。
2. 本/文/栏/码连续编辑：提交后参考文档 P95 ≤300ms 跟随；页/览/示单块编辑在
   commit 后跟随，激活期不抖动。
3. 在跨页段落的续页 fragment、跨片块、续表上激活编辑，提交仍命中正确规范块。
4. 本视图输入未闭合 fence/不完整表格时草稿不丢；修复后同一 Revision 链继续；
   码编辑器修改指定语言的代码块后，仅对应规范块更新。
5. undo/redo 在任意视图触发，全部视图一致回退，IME 原子性、选区、滚动和
   dirty/save 基线正确。
6. 多个完全相同的段落交换顺序后分别编辑，不误锚；歧义时宁可重建，不写错块。
7. 单块激活期间发生 undo、外部重载或文档切换，草稿不被静默覆盖，不写入旧版本。
8. 打印页数 = 屏显页数；字体/图片晚到后重测，provisional 测量不污染缓存；
   某块图片晚到不失效无关纯文本块，全局字体晚到按全局资源世代正确重测。
9. 纯投影刷新期间 apply 零调用；保存 watcher 回声不生成新编辑事务。
10. 测量、览构建和图表异步结果人为乱序返回，旧 Revision 永不覆盖新 Revision。
11. 示中编辑时 Esc 先取消编辑，无活编辑面时 Esc 才退出放映；步进键不抢文本输入。
12. 长文档基准记录事务、增量 hash、测量、布局、投影各阶段耗时及缓存内存，
    不用全量 O(n) 哈希/解析暗中破坏 N2。
13. Muya 自源编辑只封装、不二次 apply；外源编辑只提交一次；连续混合输入的
    Revision 顺序与实际 apply 顺序一致。
14. 人为让宿主/iframe 的 styleFingerprint、renderSchemaVersion 或资源版本
    不一致，系统先同步重建，不出现新旧样式混合或旧构建结果落屏。
15. 页与览分别验证几何：页/打印页数严格一致；览/示在 iframe 内分片和 fit
    自洽，不断言两者共享块高或页坐标。
