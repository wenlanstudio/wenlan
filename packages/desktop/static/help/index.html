文览生态由四个组件协作：文览（编辑器）、放映（md2slides）、代码运行（mdcode2run）、课堂竞答（classbuzz）。它们各自定义了「写在文档里、控制渲染或运行行为」的配置。左侧目录可切换到任意一个组件的完整清单。

本文是面向查阅的入口。四份完整清单由各项目在自己的 docs/FRONTMATTER.md 维护，本帮助窗口内的内容是它们的离线快照。有功能变更时，各项目先更新自己的文档，再由 wenlan 同步。

四组件对比

组件 配置载体 是否 YAML frontmatter 用途 核心键
文览 · 纸面叶 文档顶部 --- 围栏 是（仅 2 键） 纸型 / 纸面主题 paper、paperTheme
放映 · md2slides 文档顶部 --- 围栏 是（16 键） 封面、分页、主题、放映形态 title、theme、headingDivider、toc
代码运行 · mdcode2run 文档顶部 --- 围栏 是（code-exec: 段 + 顶层） 执行环境 / 连接配置 code-exec.java.JAVA_HOME、host
课堂竞答 · classbuzz 正文 <!--quiz--> 注释 + 服务端房间 否 题目与竞答房间 answer、limit、id

什么是 frontmatter

YAML frontmatter 是写在 Markdown 文档最顶部的一段 --- 围栏块：

---
title: 我的讲义
theme: lecture
---

# 正文从这里开始

通用规则（各项目略有差异，详见各组件页）：

  • 必须位于文档最顶部，围栏两侧允许空格或制表符。
  • 标量解析：数字、布尔、去引号字符串；不引第三方 YAML 库。
  • 有 frontmatter 则作者声明全算数，未声明的键不补默认值（无配置时走各项目内置缺省）。
  • 未知键通常静默忽略，不报错。

跨组件要点

  • 文览的 frontmatter 不归自己全管：muya 渲染层无键语义，纸面叶只认 2 键，放映键完整委托给内置 md2slides。
  • 同一份讲义可能同时被多个组件读：讲义里既写 theme:（md2slides）又写 <!--quiz-->（classbuzz）是常见用法——前者控制放映，后者出题，互不干扰。
  • 优先级模型各不相同：
    • md2slides：show/page > 壳 config > 引擎缺省；headingDivider/theme/... > DECK_DEFAULTS
    • mdcode2run：fence 块级标注 > 文档 frontmatter > 引擎配置（秘密层）
    • 文览纸面叶：独立正则各取各的，未声明回退默认
    • classbuzz：题注字段 > 引擎缺省；房间状态由服务端持有
  • 密码不进 frontmatter（mdcode2run）：秘密只放引擎配置，这是分享讲义的前提。
  • page 与 paginate 是两个不同的键：前者管放映翻页粒度，后者管页脚打不打页码。

易错点

  • doc-type（md2slides 旧文提过）未实现，写了无效。
  • <!-- pagebreak -->（纸面叶）与 <!--quiz-->（竞答）都是正文注释标记，不是 frontmatter。
  • classbuzz 讲义顶部写 --- 块不生效——它不解析 YAML。

0. 范围

  • 文览自身只消费**纸面叶（paper）**的纸型/纸面主题两键（见 §1）。
  • 编辑器内核 muya 把 front-matter 当通用块渲染（pre.mu-frontmatter），没有任何键语义； 偏好设置里的 frontmatterType 只影响新建 front-matter 块的围栏风格（- / ; / + / {），不解析键值。
  • 放映（deck）链路的 front-matter 键由内置的 md2slides 消费，不归本仓库管—— 见 ../../md2slides/docs/FRONTMATTER.md（本仓库 packages/desktop/resources/md2slides/ 是它的构建副本）。

paper a4 / letter 纸型。键名大小写敏感（须写 paper:），值大小写不敏感；未知值按未声明处理 A4（屏测与打印链同源回退）

0. 解析规则（frontMatter.js，唯一实现）

  • 只认文档最顶部的 --- 围栏块：/^[ \t]*---[ \t]*\r?\n[\s\S]*?\r?\n---[ \t]*\r?\n?/。
  • 标量解析，不引 js-yaml：数字、布尔、去引号字符串。date: 2026-10-24 是字符串不是日期对象。
  • 无 front-matter 的文档由 compose 注入默认（headingDivider: 3 + theme: lecture）； 有则作者的话全算数，未声明的键不补默认值。
  • 未知键被忽略，不报错。

1. 元数据键（deckMeta，11 键）

去向：封面页 + PPTX 文件属性（title→标题、subtitle→主题、author→作者）。

键 值 去向 缺省
title 文本 封面题名；PPTX 文件属性·标题 null（无 title 则无封面页）
subtitle 文本 封面副标题；PPTX 文件属性·主题 null
author 文本 封面作者；PPTX 文件属性·作者 null
date 文本/数字 封面日期；字符串原样进 IR，sidecar（Python）strptime null
datetime 文本 date 的别名（marp 兼容）；两边都写 date 优先 —
book 文本 书籍/课程名 → 页眉左侧内容源 null
header true / false / "文本" 页眉三态：开 / 关 / 自定义文本 true
footer 同上 页脚三态 true
keywords A, B 或 [A, B] 正文命中即高亮（分隔符 , ， ; ； 、，大小写不敏感去重）；只驱动渲染，不进 PPTX 属性 []

2. 渲染键（frontMatterPairs → compose 消费）

键 值 说明 缺省
headingDivider 1–6 第 N 级标题起切页（钳到 1–6） 3

paginate true 打页码（严格 === true 才生效） 不打

doc-type（USAGE 旧文提及）：未实现，代码无消费点，写了无效果。

3. 不是 front-matter 的东西（别写错位置）

  • 抢答题：正文里 <!--quiz {"answer":"B","limit":30}--> 标记，见 core/quiz/parse.js 与 USAGE §3.7。
  • 分栏：正文里 <!-- begin/split/end --> 注释。
  • 块级标注（mdcode2run 的 demo / file= 等）：fence info-string，见生态根目录 AUTHORING-SPEC §二。

0. 解析规则（front-matter.js）

  • 配置三层的前言层：fence meta（块级）> front-matter（本文档）> 引擎配置（秘密层）。
  • 查找顺序：code-exec.<section>.<key>（新，文档级默认）→ 顶层 <key>（旧写法，仍认）。
  • 键名大小写不敏感（find() 归一比较）。
  • 只解析缩进映射 + 标量：不碰列表 / 嵌套深层 / 含空格的长文本值 （那些属于 title / tags 这类展示性元数据，不是配置）。
  • 密码不在此列——秘密只放引擎配置（宿主偏好），前言层无权读取。

1. code-exec: 段（文档级执行默认）

键 语言 值 说明
code-exec.java.JAVA_HOME java JDK 根目录或 bin 目录 每次运行现取（换文档换 JDK）
code-exec.java.class-path java ; 分隔字符串或数组 dir/* 展开为该目录全部 jar；相对路径基于文档目录
code-exec.python.PYTHON_PATH python 解释器路径 相对路径按 cwd 解析
code-exec.mysql.HOST mysql 标量 连接覆盖；PORT / USER / DATABASE 同理
code-exec.mysql.PASSWORD — 禁止 秘密只在引擎层（分享讲义的前提）

段名（java / python / mysql…）即语言段；同一段内键大小写不敏感。

2. 顶层旧写法（仍认，优先级低于 code-exec: 段）

键 别名 说明
host hostname ssh_host remote_host 远端主机（配合块内 [user@host]$ 提示符或壳配置 MODE=remote）
user username ssh_user remote_user 远端用户名
（其余顶层标量键） — 凭据表：键=用户名、值=密码；sudo 自动改写 sudo -S 喂密码
JAVA_HOME / class-path — java 旧顶层写法（code-exec.java.* 优先）

项 内容

1. 题注字段（<!--quiz ...-->）

标记必须是独占一行的注释（最多 3 空格缩进），紧跟其后的第一个段落是题干、 再紧跟的第一个列表是选项；两者之间不能插入别的块，否则标记被当作普通注释忽略。

两种写法都认：

<!--quiz {"answer":"B","limit":30,"id":"q1"}-->
1 + 1 = ?

- 1
- 2
- 3
- 4

<!--quiz answer=B limit=30-->
1 + 1 = ?

- 1
- 2
- 3
- 4
字段 值 说明 缺省
answer A–F 字母（忽略大小写）或 0 基序号 归一为 0 基序号（B → 1）；认不出或没写 = null，面板报「没设答案」，不猜 null
limit 秒数 钳到 5–300 秒；别名 limitsec / limitSec；产出为 limitSec 30
id 文本 题号，透传到 qid；不写则按出现顺序 q1 / q2… qN
  • JSON 优先；JSON 不合法时退回 key=value 简写（值可带引号，但不能含空格）。
  • 参数完全读不懂、或找不到题干/选项时，标记原样留在文档里（当普通注释）， 方便老师看出笔误，不会静默吞掉。
  • 空标记 <!--quiz--> 合法：答案为空、时限 30 秒。

2. 房间配置（WS 协议）

题目由讲义的「发放」按钮经 host_open 送入房间，房间状态全部由服务端持有：

消息 载荷 说明
host_create {} 创建房间，回 host_ok{room, token, joinUrl}
host_attach {room, passcode} 第二个教师端（放映讲义侧）凭房口令换 host 角色
host_open {qid, stem, options, answer, limitSec} 开题；answer / limitSec 即题注字段
question_open {qid, stem, options, limitSec, deadline} 广播给学生，answer 不下发
host_abort / host_close / host_next {} 作废 / 提前收卷判分 / 结束本题
host_reset_scores {} 全班成绩清零
  • 讲义侧以 host_attach（房间号 + 房口令）接入，题目不写在服务端配置里。
  • question_result 回讲义底部浮层：正确答案 / 选项分布 / 最快 / 榜单。
  • 清零会同时抹 room.scores、每人 stats{answers, correct, fastestMs}、room.lastResult； 有题在进行中一律拒清。

3. 优先级

题目字段   讲义 <!--quiz {...}-->  >  parseQuizMeta 缺省（limit 30 / answer null）
房间状态   服务端 room.*            >  客户端（只读，不可覆盖）
放映键     md2slides front-matter  >  壳 config > 引擎缺省（与题注互不相干）

4. 注意

  • 同一份讲义可同时被 md2slides 与 classbuzz 读：--- 顶栏里的 theme / headingDivider 归放映，正文的 <!--quiz--> 归竞答，互不冲突。
  • 不要把放映 / 纸面的 front-matter 键写进 classbuzz 讲义期待它生效——本组件不解析 YAML。
  • 题注是 markdown-it core 规则在 token 流上消费的（渲染后注释已被 sectionize 丢掉）， 不是渲染完再遍历 DOM；宿主凭 data-md2s-quiz* 属性认题。
  • 多选 / 判断 / 题库 JSON 尚未落地，当前只支持单选字母。
